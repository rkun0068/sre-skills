# SysRq 使用规范

所有 sysrq 操作都要写 `/proc/sysrq-trigger`，需要 root 权限，并且**每次都必须经过确认门**。

## 前提检查

- `kernel.sysrq`：
  - 写 `/proc/sysrq-trigger` 只需要 root，**不受**这个值的限制；
  - 这个值只控制通过键盘触发的组合键；
  - 记录这个值是为了在报告中说明。
- 确认内核日志能被保存下来：通过 journal、串口或 netconsole。否则输出会丢失。

## 可以申请使用的键

| 键 | 作用 | 风险 | 使用条件 |
|---|---|---|---|
| `w` | 打印所有 D 状态任务的栈 | 低。日志量和 D 任务数量成正比 | 只读快照拿不到栈时，首选这个 |
| `l` | 打印所有 CPU 当前的栈（NMI backtrace） | 低 | 怀疑 soft lockup 或 hard lockup |
| `m` | 打印内存信息 | 低 | 怀疑内存问题 |
| `t` | 打印**所有**任务的栈 | **中**：任务很多的机器上日志量巨大，通过慢速串口输出时，本身就可能引发 soft lockup | `w` 不够用，而且任务数不多（例如少于 2000）时才用 |
| `c` | **立即让内核崩溃**，触发 kdump | **极高：机器会立刻宕机** | 只能在用户书面同意、确认 kdump 已就绪、并约定好时间窗口之后执行 |

执行方式（经确认后）：

```bash
ssh <host> 'echo w | sudo -n tee /proc/sysrq-trigger >/dev/null; sudo -n dmesg -T | tail -300'
```

## 禁止由 Claude 发起的键

| 键 | 原因 |
|---|---|
| `b` | 立即重启，不同步、不卸载文件系统，可能导致数据损坏 |
| `o` | 立即关机 |
| `e`、`i` | 向所有进程发送 SIGTERM / SIGKILL |
| `s`、`u` | 在系统卡住时执行同步或只读重挂载，自身也可能卡住 |
| `f` | 手动触发 OOM killer |

如果用户确实需要执行这些操作，只说明其风险，让用户自己执行。
