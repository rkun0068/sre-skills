# 无障碍与包容性

## 无障碍检查清单

**语言**
- [ ] 英文句子尽量少于 26 个词，每段的第一句就是要点。
- [ ] 不用双重否定；缩写在首次出现时写出全称。
- [ ] 正文和标题中用 "and"，不用 "&"；少用全大写和驼峰写法。
- [ ] 少用感叹号、问号和分号，因为有些屏幕阅读器会跳过标点。

**结构**
- [ ] 只有一个一级标题，标题层级不跳级，不出现空标题。
- [ ] 标题具体且不重复；大段文字拆成段落、列表或小标题。

**链接**
- [ ] 链接文字脱离上下文也能看懂，不写 "click here"。
- [ ] 说明会下载文件、在新标签页打开或在页内跳转的链接；相邻的链接之间要有分隔字符。

**图片与媒体**
- [ ] 每张图片都有 alt text；纯装饰的图片用空的 alt text。
- [ ] 图片里的信息在正文中也有对应的文字。不用截图代替文字、代码或终端输出。
- [ ] 优先使用 SVG；视频提供字幕或文字稿；不用闪烁的元素。

**表格**
- [ ] 表格前有引导语；只有第一行和第一列作为表头；不合并单元格。

**颜色与视觉提示**
- [ ] 不只靠颜色、图标、大小或位置传达信息，同时配上文字。
- [ ] 不用 "above / below / right-hand side"，改用 preceding / following，或者直接写元素的名称。

## 包容性语言

- 用词替换见 word-list.md 中的"包容性用词"一节。优先改写整个句子，而不是只替换一个词。
- 代码中已有的、不符合包容性要求的名称（例如某个参数叫 `master`）：首次出现时直接引用并加上 code 字体，之后的叙述中使用推荐的说法。
- 不用以美国为中心的节日、体育、谚语等表达。
- 示例中的人名，在性别、年龄和地区上要有多样性。
- 描述残障人士时，用 "people with disabilities"；避免 "suffering from"、"wheelchair-bound"、"normal"（指非残障人士）这类说法。
- 不用 "careful"、"proper" 这类空泛的要求，改为给出具体的指令。
