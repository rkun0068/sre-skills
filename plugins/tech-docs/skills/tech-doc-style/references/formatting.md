## 文字格式

| 内容 | 格式 | 示例 |
|---|---|---|
| UI 元素 | 粗体 | Click **Save**. |
| 首次定义的术语 | 斜体 | A *shard* is a partition of a database. |
| 强调 | 尽量少用，靠措辞本身表达 | |
| 代码、命令、参数、文件名、类名、方法名、HTTP 状态码、终端输出 | `code` | Open `config.yaml`. The server returns `404 Not Found`. |
| 占位符 | `UPPER_SNAKE_CASE`，放在 code 字体里 | `--project=PROJECT_ID` |
| 多行代码 | 带语言标记的代码块 | ```` ```bash ```` |
| 标题和导航 | sentence case | Set up your project |
| & 符号 | 改写成 and | 照抄界面上的文字时除外 |

在 Markdown 中，粗体用 `**`，斜体用 `_`。不要用 `__` 表示粗体，因为在源文件里容易和斜体混淆。

## 标题

- 用 sentence case，内容具体、不重复，便于读者浏览。
- 任务类标题以动词原形开头，适用于 quickstart、how-to 和教程，例如 "Create a cluster"。
- 概念类标题用名词短语，例如 "Cluster architecture"。
- 标题不以 -ing 开头。Billing、Pricing 这类已经固定下来的名词除外。
- 一页只有一个一级标题，页面里的标题不要和页面标题重复；标题层级不跳级；不要出现下面没有内容的空标题。
- 标题里不放链接；尽量不放代码，确实需要时加上说明性的名词，例如 "The `init` command"；不用数字表示顺序。
- 只适用于部分读者的章节，在标题里标出：加上前缀 "Optional:"，或后缀 "(optional)"。
- 引出下级小节时写 "the following sections"，不写 "this section"。

## 列表

| 类型 | 适用 |
|---|---|
| 编号列表 | 有先后顺序的内容：步骤、阶段、优先级。子步骤用 a、b、c，再下一级用 i、ii、iii |
| 项目符号列表 | 没有顺序的内容：选项、示例。写清楚是否每一项都必须 |
| 描述列表 / 带粗体标题的列表 | 术语加解释，例如 `- **Term**: description` |

- 列表前用一个完整的句子引出：后面紧跟列表时用冒号结尾；中间隔着其他内容时用句号。如果上方的标题已经说清楚了，可以省略引导语。
- 各项结构平行：如果一项以动词开头，其他项也都以动词开头。
- 每项首字母大写，以句号结尾。以下情况不加句号：只有一个词、不含动词、整项都是代码、整项只是链接或标题。同一个列表内保持一致。
- 只有一项时不要用列表。
- 写在正文句子里的列举，用 serial comma（"A, B, and C"），不用 etc.。

## 表格

- 表格前用一句话说明表格内容。
- 只有第一行和第一列可以作为表头；不合并单元格。
- 每一项有多个属性时才用表格，简单的罗列用列表。
- 尽量不要把表格放在编号步骤中间。

## 提示框

读者经常跳过提示框。所以先尝试把内容写进正文，确实需要单独突出时，才使用提示框。

| 类型 | 用途 |
|---|---|
| Note | 有用但不影响完成任务的补充信息 |
| Caution | 提醒读者谨慎操作 |
| Warning | 最强的级别：不可逆操作，或可能丢失数据、金钱、安全性。要写出后果 |

不要用 Note 写：交叉引用、前提条件（应该放在步骤之前）、完整的操作步骤、完成任务必需的信息。不要连续放两个提示框，也不要嵌套提示框。

## 链接与交叉引用

- 链接文字用目标页面的标题，或者一个简短的描述性短语，并且放在句子里。不用 "click here"、"this document"，也不直接用 URL 作为链接文字。
- 交叉引用的写法："For more information, see [Page title](...)." 或 "For more information about X, see ..."。用 "see"，不用 "on"。
- 要明确告诉读者以下特殊情况：链接会下载文件（写明文件类型）、在新标签页打开、跳到本页的某一节、离开文档站点。
- 只链接最相关的内容，同一页里不要重复链接同一个目标。能用一两句话说清楚的，就不要让读者跳出页面。
- 标点放在链接外面；带链接的文字不加引号。

## UI 元素

- 用界面上显示的名称，加粗。不要把元素名称当作动词，例如写 "In the **Name** field, enter ..."，而不是 "**Name** the account"。
- 动词：click、select、enter / type、press、turn on / turn off、go to、drag。
- 介词：dialog、field、list、menu、pane、window 用 "in"；page、tab、toolbar 用 "on"。
- 菜单路径：**File > Settings**。只用于菜单项，不要混入其他类型的元素。
- 快捷键：先写 Windows / Linux 的，再在括号里写 macOS 的。例如 "Press Control+C (or Command+C on macOS)."；修饰键写全称，字母大写。

## 日期、数字与单位

- 日期：`2026-10-23`，或 "October 23, 2026"。不写 `10/23/2026` 这种在不同地区含义不同的格式。
- 时间：写明时区，例如 "14:00 UTC"。
- 数字和单位之间加空格（`10 GB`、`100 ms`）。百分号除外（`50%`）。
