# 分步操作（procedure）

## 结构

1. **前提条件放在第一步之前**：需要的权限、工具、信息和软硬件，单独列成一节，通常叫 "Before you begin"。
2. **引导语**：写成一个完整的句子。
   - 推荐："To change the password, follow these steps:"
   - 不推荐："To change the password:"（句子不完整）
   - 如果上方的标题已经说明了要做什么，可以省略引导语。
3. **编号步骤**：每一步只包含一个动作，以祈使动词开头，写完整的句子，各步骤之间结构平行。
4. **只有一步时**：不用编号列表，写成一句话，或者用一个项目符号。
5. **子步骤**：用 a、b、c 编号，再下一级用 i、ii、iii。

## 复杂步骤内部的顺序

1. 动作
2. 要运行的命令（代码块）
3. 解释占位符（"Replace the following:"）
4. 关于这条命令的补充说明
5. 命令的输出（如果对读者有用）
6. 执行结果或原因，单独成段

## 句子写法

| 规则 | 推荐 | 不推荐 |
|---|---|---|
| 先说位置或上下文，再说动作 | In the admin console, open the **Users** page. | Open the **Users** page in the admin console. |
| 先说目的，再说动作 | To save your work, click **File > Save**. | Click **File > Save** to save your work. |
| 先说动作，再说结果 | Click **Run**. The results appear in the editor. | |
| 需要说明原因时，放在动作之后 | Save the key file in a secure location. You need it later. | |
| 可选步骤 | Optional: Enter a description. | (Optional) Enter a description. |
| 不写 please | Enter your name. | Please enter your name. |
| 不写 "run the following command"，而是说明命令的作用 | Install the dependencies: | Run the following command: |
| 不用方向词 | In the **Details** pane, … | In the right-hand pane, … |
| 需要按键时写明 | Enter the name and press **Enter**. | |

## 其他

- 如果"目的放在前面"会让一个必需的步骤听起来像是可选的，改用冒号句式，例如 "Sort the rows by date:"。
- 有多种方法完成同一个任务时，只写一种对所有人都适用的方法：最短，而且不依赖鼠标。确实需要写多种方法时，用标签页或不同的小节分开。
- 一个流程已经在别处写过时，直接链接过去，不要重复。
- 流程分散在多个小节里时，每一节的第一步都要重新交代所处的上下文。
- 步骤尽量少，不要在步骤之间插入大段解释。
